## Source audit

- historical_replay.py: finite input windows but indicators loaded over history; optional network AI path and fixed-name output overwrite exist. Not invoked by the new pipeline. Runtime timestamps prevent byte-identical exports.
- outcome_labeller.py: labels future 5/10/20 bars and directional returns/MFE/MAE; no TP/SL execution simulation. Labels include current timestamps.
- filter_validation.py: chronological index split without horizon purge; outcomes near the boundary can consume the validation interval.
- execution_baseline.py: purges crossing exits and uses lagged spread proxies; EARLY/LATE are exploratory partitions, not a certified holdout. Later feature windows may reuse earlier context.
- execution_diagnostics.py: read-only verification of saved hashes/rules and spread-proxy CSV; does not turn explored periods into a holdout.
- No cash_replay*.py source is present. Three related bytecode cache names exist, but bytecode/output filenames are insufficient to reconstruct source/settings provenance.
- cash_replay_v3_outcomes.csv and cash_replay_v3_outcomes_80bar.csv have identical bytes; suffixes alone cannot establish different horizons.
- CSV parsing skips blank physical lines: the pilot files contain 10 data records, and execution_baseline_trades.csv contains 609 records. Earlier physical-line counts must not be treated as sample counts.
- Stored source-hash mismatches documented in TEST_AND_DATA_PROVENANCE.md remain unresolved; no ledger was updated.
- MQL5 full compile and broker execution are not verified; C++ harnesses remain unrun here because g++ was unavailable.
